Invoice Processing Pipeline

  • Networked scanner
  • Google Drive
  • Apps Script
  • AI model
Problem
Paper invoices came off the scanner as unnamed PDFs that someone had to open, read, rename, and file by hand.
Approach
Treat the scanner folder as an inbox. Each new PDF is picked up automatically, read by an AI model, and filed without anyone touching it.
What I built
A pipeline connecting a networked scanner, Google Drive, Google Apps Script, and an AI model. The script sends each PDF to the model, gets back the vendor and date, renames the file, and moves it into that vendor's folder.
Result
Invoices are renamed and filed into per-vendor folders with no manual handling.

Financial Tracking System Rebuild

  • Google Sheets
  • SUMIFS
  • Data migration
Problem
Transactions and cash flow lived in two disconnected processes, so reporting meant reconciling them by hand.
Approach
Combine both into one workbook where the numbers calculate themselves, then migrate the existing records into it.
What I built
A unified four-tab workbook with SUMIFS formulas that roll transactions up into cash flow automatically. During the migration I found and fixed category mismatches and a lookup collision.
Result
One system replaced two disconnected processes.

Tuition Mail Merge

  • Google Sheets
  • Apps Script
  • Gmail drafts
Problem
Every family needed a personal tuition notice showing their own payment schedule, and writing 60 of them by hand invites mistakes.
Approach
Generate every email from the spreadsheet, but never send automatically. A person reviews each one first.
What I built
A Sheets and Apps Script mail merge that produces 60 personalized notices, each with a payment table built from that family's data. The emails land in Drafts for review before sending.
Result
Sixty personalized notices generated from one sheet, checked in Drafts, then sent.

Advanced American Academy

  • HTML
  • CSS only
  • Lighthouse 100
  • GitHub Pages
Problem
A school website has to work for every family, including people using screen readers, keyboards, or small phones.
Approach
Start from semantic HTML and accessibility requirements, and skip JavaScript entirely so nothing can break.
What I built
A four-page responsive site in semantic HTML and layered CSS with no JavaScript: cascade layers and design tokens, CSS grid with subgrid, container queries, and clamp(). Tested at 1280, 768, and 375 px and at 200% zoom, and deployed on GitHub Pages with a documented release checklist.
Result
Lighthouse Accessibility 100 and SEO 100, axe reporting 0 issues, and valid JSON-LD.

Balance

  • React
  • Adaptive goals
  • Saved history
Problem
Generic goal lists don't react to how a person is actually doing.
Approach
Make a short check-in the center of the app, and let each result shape the next goals.
What I built
A React check-in app that scores seven wellbeing pillars, adapts goals to prior results, and stores a history of past sessions.
Result
A working app where progress over time is visible, because every session is saved.

School Website Improvements

  • Lighthouse
  • WordPress
  • Performance · accessibility · SEO
Problem
The school's WordPress site had never been audited, and it collects family data without a privacy policy.
Approach
Let a Lighthouse report set the priorities, fix what it flags, and close the privacy gap.
What I built
A Lighthouse-driven audit and remediation of the site's performance, accessibility, SEO, and best practices, plus a new privacy policy that I'm drafting and publishing.

Fixes made against the report's findings, and a privacy policy to meet disclosure expectations for a site that collects family data.

Sit A While

  • Creative brief
  • Mood board
  • Lighting plan
  • Test shots
Problem
Arabic coffee is often seen as a cheap, nostalgic staple. The campaign had to reposition it as a premium ritual of hospitality.
Approach
Plan the whole shoot on paper first: study commercial references, build a mood board, and previsualize the lighting before shooting anything.
What I built
A pre-production package for an Arabic coffee campaign: creative brief, competitive reference analysis, mood board, lighting previsualization, three test shots with written critique, a risk assessment, and a revised production plan. The test shots are in the Design gallery, and the full write-up is on Behance.
Result
A complete package that runs from brief to tested shots to a revised plan.

Sanaré Animated Identity

  • Illustrator
  • Photoshop
  • After Effects
Problem
The Sanaré mark had to read as clinical instrumentation to care teams and as an everyday wearable to patients.
Approach
Extend the static mark into motion, so one identity works as an app intro, a loading state, or a site hero.

Design Is Not For Sale

  • Editorial layout
  • Display type
  • Print build
Problem
Design is too often used to push people toward purchases they do not need. The booklet argues that designers carry a responsibility to be intentional with their work.
Approach
Write the argument first, then let the layout carry it: oversized, tilted display type against calm, readable text.
What I built
A design-ethics manifesto booklet that I wrote and designed: a multi-spread editorial layout with a layered display-type system, an original long-form argument, and a reader-spread print build. The cover, spreads, and back cover are in the Design gallery.
Result
A finished booklet, shown in print mockups.

Typographic Posters

  • Typography
  • Information design
  • Poster layout
Problem
Type alone had to carry two very different jobs: one poster that is expressive and experimental, and one that has to make a lot of text easy to scan.
Approach
Push the letterforms as far as they go in the first poster, and use a strict hierarchy in the second.
What I built
An experimental type poster built entirely from layered and rotated letterforms, and an information-design poster that sets all thirty articles of the UN Declaration of Human Rights into a scannable two-column hierarchy.
Result
Two finished posters, both in the Design gallery.
